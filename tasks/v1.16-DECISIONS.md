## 8E5S6tV6 — Explain: FIT UP tab

**Decision:** The "Fit-up" tab on the vendor module page (v1.14 Story 9.2.1)
is the **per-module slice** of the org's Fit-Up catalog. It mirrors what
already lives at **Manage → Fit-Up Catalog** but filters down to items
where the current module's id is in `fitUpItems[].moduleIds`.

Operators see only the items that belong to **this** module, can edit
inline, and add items pre-assigned to this module. Edits write to the
**same** Firestore docs as Manage → Fit-Up Catalog — there is **only one
source of truth**, last-write-wins, audit captures who.

**Why it exists:** so a module owner (Yamaha, Highfield, etc.) can manage
fit-up data without bouncing to the master catalog and filtering by hand.

**Where it lives:** vendor module workspace → **Fit-up** tab (between
Promotions and Settings on Yamaha). Same component
(`ModuleFitUpTab`) can be mounted on any other vendor workspace with one
line — held off Boats / Trailers until a real ask comes in.

## Cl0bRhFo — How to fit images to DEALER FIT ITEM

**Decision:** Dealer-fit selection cards on Step 5 of the quote flow read
their image from the **first item's catalog data** via `resolveImageUrl`.
That means:

1. The image lives on the **underlying part / dealer-fit item** in the
   catalog (e.g. on the Yamaha module's `parts/` rows, or on the v1.10
   `serviceParts` rows depending on the source).
2. The dealer-fit "selection" itself doesn't carry an `imageUrl` field
   today — it inherits from the first item it groups.

**To set an image:**

- For Yamaha parts: Manage → Pricing Manager → Yamaha → Catalog tab →
  pencil-edit a part → Image URL field.
- For Highfield + boat-side dealer-fit items: edit the part on its source
  module workspace.

**Recommendation if this becomes a frequent ask:** add an explicit
`imageUrl` field to the `DealerFitSelection` schema so the selection can
override the inherited item image. Logged as v1.17 candidate.

## N29OaRni — Admin tab

**Decision:** No new top-level "Admin" tab will ship. Admin-style
surfaces already split across two places by design:

| Surface | Where | Audience |
|---|---|---|
| Org-level settings (defaults, permissions, modules, fit-up catalog, service catalog) | **Manage** (org slug → `/manage`) | Org admins |
| Per-vendor workspace (catalog, pricing, promotions, fit-up scope, settings) | **Module page** for each subscribed vendor | Module owners |

A single "Admin tab" would either duplicate one of these or split admin
controls across two places — neither helps. If a future surface needs an
admin-only home, it goes under `Manage` with the existing
`can_access_*` permission gates.

## 9Y7UnGZJ — Recommended image sizes for uploads

**Decision:** Recommended sizes documented here so operators uploading
catalog imagery hit good results first try. Each is the **minimum**
useful size; larger is fine (the PDF preload pipeline downsamples).

| Surface | Aspect | Recommended min size | Notes |
|---|---|---|---|
| Boat cover image | 16:9 | 1600 × 900 px | Used as hero on proposal PDF cover; gets downsampled to 1200px wide max for embed. |
| Boat variant (colour) image | 4:3 | 1200 × 900 px | Hero on the Vessel band of the PDF + carousel slide during build. |
| Motor image | 1:1 or 4:3 | 800 × 800 px | Used on the Motor band + the catalog row. Yamaha CDN is blocked server-side — upload via Manage → Motors → Upload Photo for it to render on PDFs. |
| Trailer image | 4:3 | 1200 × 900 px | Used on the Trailer band. Same upload affordance on Manage → Trailers. |
| Dealer-fit item image | 1:1 | 600 × 600 px | Small square on the dealer-fit picker card. |
| Fit-up item image | 1:1 | 600 × 600 px | Small thumbnail on the catalog + the picker card. |
| Optional feature image | 1:1 | 600 × 600 px | Thumbnail on the Factory Options grid (Step 2). |
| Org primary logo | wider than tall | 600 × 200 px (≥ 3:1) | Used on PDF header. Larger boost in v1.16 (bvAyUQVR) supports up to 220×56 rendered. |
| Vendor logo | wider than tall | 600 × 200 px | Same as org logo. |

**Format:** PNG with transparent background for logos. JPEG or PNG for
photos. AVIF / WebP not supported by the PDF render pipeline yet (v1.17
candidate).

**Hosting:** Upload via the catalog UI (writes to Firebase Storage). The
PDF render preloads images as base64 data URLs at render time, so
operator-controlled hosting (Storage) renders reliably; vendor CDNs may
or may not (Yamaha is blocked — see CLAUDE.md).

## hSPmTAy5 — How to change image in "Choose Boat Series"

**How to:** The Boat Series picker (range card) image comes from the
Range document at:

```
data-warehouse/{vendorId}/ranges/{rangeId}.imageUrl
```

To change:

1. Go to **Catalog Manager → Highfield (or your boat brand)**.
2. Click the range you want to edit on the left sidebar.
3. On the Range editor at the top of the workspace, paste a new image URL
   into the **Image URL** field (or use the existing upload button).
4. Save.

The new image surfaces immediately on the New Quote dialog's "Select a
Series" step + the Catalog tab range cards.

**Recommended size:** 1200 × 900 px (4:3) — see 9Y7UnGZJ above.

## 2eTb7FTN — Yamaha rigging kits

**Decision:** Data setup task, not a code change.

The "rigging kits" concept fits the existing v1.11 Fit-Up + Dealer Fit
schemas — specifically:

- **As a Fit-Up Package** (Manage → Fit-Up Catalog → Packages tab):
  create "Yamaha Rigging Kit — F25", "Yamaha Rigging Kit — F70", etc.
  with the right per-tier items bundled.
- **As Dealer Fit Selections** (Manage → Dealer Fit Categories):
  one selection per kit, scoped via `applicableModelIds` (v1.16
  ZidKJczh) so the kit only shows on compatible boats.

No new code needed. The catalog admin can build these via the existing
admin UI. The cleanest path is Fit-Up Packages since that's the
Highfield + Yamaha intersection (rigging kit = packaged install) and
the v1.11 packagePrice override handles the discount math.

For the future: if the rigging-kit catalogue grows enough that bulk
admin matters, add a v1.17 "import rigging kits from xlsx" surface.
