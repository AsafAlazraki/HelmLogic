## Composition (6 stories, ~18 pts)

### Phase A — Carry-overs + inline preview (lands first)

| # | Story | Pts | Type | dependsOn |
|---|---|---|---|---|
| 1 | **1.1.2** Compatibility Rules + Highfield auto-seed | 3 | feature | — |
| 2 | **1.8.4** Quote preview button (inline PDF render) | 3 | feature | 1.5.0 (shipped v1.8) |
| 3 | **1.8.3 UI slice** `startsOnNewPage` toggle | ~1 | feature | 1.8.4 |

Phase A lands first because:
- 1.1.2 is the long-standing v1.7→v1.8 carry-over — a clean small
  feature to warm up the cycle.
- 1.8.4 unblocks 1.8.3's UI (the page-break toggle is dormant without
  an inline-render path the operator can verify against).
- 1.8.3 UI was punted from v1.8 with the schema already shipped via
  1.8.8 import/export. The checkbox is small once 1.8.4 lands.

### Phase B — Quote lifecycle

| # | Story | Pts | Type | dependsOn |
|---|---|---|---|---|
| 4 | **1.4.1** Quote Lifecycle States | 3 | feature | 1.3.1 (shipped v1.8) |
| 5 | **1.1.3** Multiple Quote Scenarios | 3 | feature | 1.3.1 (shipped v1.8) |

**1.4.1** ships the full state machine: Draft → Sent → Viewed →
Accepted / Rejected / Lost / Expired. Manual transition controls in
`proposal-view.tsx` (status badge in header doubles as a state-picker
popover). **Viewed-via-email-tracking auto-transition stays dormant**
until email decisions land — `Viewed` is still reachable manually via
the picker so the state isn't a no-op.

**1.1.3** leverages v1.8's `version + parentQuoteId` fork machinery to
make multiple-version creation an explicit "Create Scenario" action,
not a side-effect of editing-while-locked. Scenarios are sibling
quotes with a shared `parentQuoteId` and a `scenarioLabel` field
(e.g. "Trade-in option", "Cash deal", "Finance bundle").

### Phase C — SharePoint storage

| # | Story | Pts | Type | dependsOn |
|---|---|---|---|---|
| 6 | **1.3.3** SharePoint Quote Storage | 5 | feature | 1.5.0 (shipped v1.8) |

Largest single story in the cycle. Uses the extracted
`render-quote-pdf.ts` to generate the finalized PDF + uploads to a
configured SharePoint folder. Per-org config in
`organisations/{orgId}/sharePointConfig`.

## Schema decisions (locked at planning)

| Key | Decision | Why |
|---|---|---|
| **Compatibility rules author** | Engineering writes rules direct to Firestore. Admin UI deferred to v1.10+. | Same call as v1.8 plan. 3 pts vs 8. Highfield auto-seed at v1.9 ship covers the only customer that needs it. |
| **Inline preview transport** | Reuse `@react-pdf` client-side render (`renderQuotePdf()` from 1.5.0). PDF rendered to Blob → object URL → `<iframe>` inside a `Sheet`. | No new SDK; PDF render is already in-page. Same engine guarantees Preview matches Download byte-for-byte. |
| **Preview surface** | Quote builder + each content block editor in /manage. | Per the 1.8.4 acceptance — operators preview from both the quote and the block being edited. |
| **`startsOnNewPage` UI** | Single checkbox on content-block-detail. PDF-render path already pages every block today; the toggle exposes a per-block "stay on prior page" opt-out (default OFF). | Schema field already round-trips through 1.8.8 import/export. No data migration. |
| **Lifecycle states** | Full state machine ships (Draft / Sent / Viewed / Accepted / Rejected / Lost / Expired). Manual transition picker in proposal-view header. Email-driven auto-transitions stay dormant. | Avoids rewiring the state enum later when email infra ships. Viewed is reachable manually so the state isn't a dead code-path. |
| **Multiple scenarios** | Reuses v1.8's `version + parentQuoteId` fork machinery. Explicit "Create Scenario" button generates a sibling quote with shared parent + `scenarioLabel`. | No new schema. Minimum-viable UX — sibling list in the parent quote's Activity tab. |
| **SharePoint provider** | Microsoft Graph API via service-principal (OAuth client-credentials). Per-org config in `organisations/{orgId}/sharePointConfig` (siteId, folderPath, tenantId, clientId, clientSecretRef). | Standard enterprise SharePoint integration. Avoids per-user OAuth dance. |
| **SharePoint trigger** | On quote finalize (status flip to a terminal state). Not on every save — keeps SharePoint folder clean. | Aligns with existing `finalize-quote-dialog.tsx` flow. |
| **Email-dependent work** | 1.3.2 Contract Signing Pack + Viewed-via-tracking auto-transition are explicitly punted to v1.10+. | Stakeholder freeze on email-send activation. Revisit when `NEXT_PUBLIC_EMAIL_SEND_ENABLED` decision lands. |

## Pre-flight infra

### SharePoint — collaborative setup (Phase C only)

For story 6 (1.3.3) to actually upload files, an Azure app registration
+ service principal must be wired up with `Files.ReadWrite.All` /
`Sites.ReadWrite.All` Graph permissions, and the org admin must drop
the client secret into Firebase Console secrets. **Same pattern as
v1.8's `ADMIN_TASK_email-trigger-setup.md`** — operator handles Azure
+ secrets, agent guides through each step. Will be authored at start
of Phase C.

Risk if not done by Phase C kickoff: 1.3.3 stalls at upload step.
Mitigation: SharePoint write path env-flag-gated
(`NEXT_PUBLIC_SHAREPOINT_ENABLED`) so the rest of v1.9 can ship
without SharePoint provider being live, mirroring v1.8's email-flag
pattern.
