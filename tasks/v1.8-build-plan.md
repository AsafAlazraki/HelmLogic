## Schema decisions (locked at Step 1 of planning)

| Key | Decision | Why |
|---|---|---|
| **PDF render** | Client-side `@react-pdf` (reuses v1.7 path). Server-side Cloud Function deferred to v1.9. | Subagent estimated server-side at 6+ pts vs the 5 originally scoped. Total v1.8 already amber. |
| **Email transport** | Firebase Trigger Email extension (Firestore-driven via `mail/{id}` collection). | Already permissioned in `firestore.rules:164`. No new SDK. |
| **Lock trigger** | On FIRST Send. Edit-locked-quote forks via `version: 2 + parentQuoteId`. | Simpler UX than on-finalize. Pairs naturally with audit log. |
| **Lock enforcement** | Firestore Rules + UI (server-side). | Power-users with browser dev tools can't bypass. |
| **Compatibility rules author** | Engineering writes rules direct to Firestore. Admin UI deferred to v1.10. | 3 pts vs 8 pts. Highfield auto-seed at v1.8 ship covers initial population. |
| **Content lock granularity** | Per-block-type org-wide (`isLockedForQuotes` toggle on the org's content block). | Per-block-instance is too granular for 5 pts; v1.9 candidate. |
| **Fork-on-edit content** | v2 carries over content overrides; audit log fresh. | Cleanest UX. Audit log is per-quote, not per-customer-thread. |
| **1.1.3 Multiple Scenarios** | Deferred to v1.9. | Schema-significant; subagent says 5+ pts after PDF treatment decided. |
