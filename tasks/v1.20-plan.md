# v1.20 — Plan (Quote-to-Contract lifecycle + variation surfaces)

**Theme**: Take a sent quote through to a signed contract with a deposit on record. Land the variation editor + customer accept page on top of the v1.19 schema foundation.

**Status**: Planning. No code written yet.
**Branch**: same dev branch, `claude/app-overview-wKiZ1`.

---

## Story slate (6 shippable + 3 NSM-Hub conditional + 2 deferred)

### Phase A — Quote-to-contract (4 stories)

- **2.4.1 Convert Quote → Contract**
  - A locked + accepted quote can be converted into a contract doc with a fresh contract number, snapshotted line items, and a `contractState: 'pending-signature'` field.
  - New collection `users/{uid}/quotes/{qid}/contracts/{cid}` (one-to-many to support re-contracts after major variations).
  - Convert action on the proposal view header. Snapshot is immutable; further variations write to the v1.19 variations collection.

- **2.4.2 Deposit Recording (with receipt PDF)**
  - On a converted contract, salesperson can record a deposit: amount, payment method (cash / EFT / cheque / card), date, customer reference.
  - Generates a receipt PDF using the v1.18 `pdf-branding.ts` lib (first real consumer of the shared tokens).
  - Storage at `users/{uid}/quotes/{qid}/contracts/{cid}/deposits/{depositId}` with a `receiptPdfUrl` after render.

- **1.4.4 Quote Validity / Expiry**
  - Per-quote `expiryAt` field; per-org `defaultQuoteValidityDays` setting (default 30).
  - Background-less: the proposal view renders a banner when expired; quote-flow Finalize sets the expiry from `now() + validityDays`.
  - Expired quotes can't be sent or converted; banner offers "Reissue with new expiry" which re-stamps `expiryAt` + writes an audit-log event.

- **1.3.2 Contract Signing Pack Generation**
  - Bundles the contract PDF + the latest accepted variations + the receipts into one multi-document pack ready for customer signature.
  - PDF assembly via `@react-pdf` with the v1.18 branding lib.
  - Output: a single PDF at `users/{uid}/quotes/{qid}/contracts/{cid}/signing-pack-{ts}.pdf`.

### Phase B — Variation surfaces (2 stories)

- **2.3.1 Quote Variations — editor + send pipeline**
  - Layers UI on top of the v1.19 schema. Salesperson surface: "Create variation" action on a locked quote, variation editor with add / remove / priceAdjust line types, draft/sent status, send-variation email pipeline mirroring v1.13.
  - Variation PDF render (delta + new total only) using the v1.18 branding lib.

- **2.6.3 Customer Agreement on Variation**
  - Public accept page at `/accept-variation/{token}`. Signature pad, IP/UA capture, one-time-use token consumption.
  - Salesperson dashboard "Pending customer agreement" pill.

### Held / Deferred from current v1.20 Firestore slate

- **8.2.1 Reporting & Analytics Dashboard** retargeted v1.20 → v1.21. Different problem area; the quote-to-contract focus stays tighter without it.
- **5.2.1 Brand & Dealer Isolation (RBAC + leakage tests)** retargeted v1.20 → v1.22. Foundational security work that needs its own design pass (cross-org leakage tests, sub-dealer isolation rules) and doesn't fit alongside customer-facing surfaces.

## Risk / unknowns

- **2.4.1 contract snapshot immutability**: easy to slip into "we'll just edit the contract doc" and break audit. Discipline: contract is write-once; new changes flow through variations (v1.19/2.3.1) or a NEW contract doc (handled by re-convert).
- **2.4.2 receipt PDF as first real branding consumer**: this is the first PDF other than the proposal-pdf to consume `pdf-branding.ts`. Risk = the branding lib's shape was right for v1.18 but wrong for receipts. Mitigation: build the receipt PDF first, see what tokens are missing, adjust the lib BEFORE the contract pack story (1.3.2) consumes it.
- **1.4.4 expiry timezone**: AU is mostly AEST/AEDT. Store `expiryAt` as a Firestore Timestamp (UTC); render in the org's timezone (`organisation.timezone`, default Australia/Sydney). Document the rule.
- **2.3.1 variation PDF format**: delta-only PDF is new. Risk = first one looks wrong. Mitigation: render a sample early, iterate before locking.
- **2.6.3 public accept page**: unguessable token in URL, one-time-use, no login required. Document the threat model and write a security-focused regression test.
- **New Firestore paths** (contracts, deposits, contract signing packs in storage): each one needs a `firestore.rules` entry + an extension to `tests/firestore-rules-deployed.spec.ts`. Don't slip the rules deploy.
- **Browser walkthrough rigor**: every new surface in v1.20 lands with a `tests/v1.20-*.spec.ts` browser test that runs against the dev URL BEFORE the ticket is marked complete. Per the v1.18 / v1.19 lesson.
