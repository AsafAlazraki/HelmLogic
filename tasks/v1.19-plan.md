# v1.19 — Plan (Pricing discipline + variations)

**Theme**: Tighten the pricing layer. Make low-margin quotes visible to a GM before they go out. Bring fit-out pricing under per-model control instead of one-size-fits-all. Add variations (priced delta sheets) onto contracts so a "we'll throw in the dealer-fit pack" change doesn't get lost in email.

**Status**: Planning. No code written yet.
**Branch**: same dev branch, `claude/app-overview-wKiZ1`.

---

## Story slate (4 shippable + 1 deferred + 3 NSM-Hub conditional)

### Phase A — Pricing discipline (3 stories)

- **2.2.1 Margin Threshold Enforcement + GM Override**
  - Per-org `marginThresholdPct` setting (default 15%) on the organisation doc.
  - Live quote-flow widget shows the running margin %. Bands: red < threshold, amber within 5pts above, emerald clear.
  - Below-threshold quotes can't finalize without a GM override (`can_override_margin` permission flag from v1.11). Override writes an audit-log entry with the user uid + reason.
  - Foundation for v1.20's reporting on overridden quotes.

- **2.1.2 Model-Specific Fit-Out Pricing (Basic / Moderate / Complex)**
  - Each boat model gets a 3-tier fit-out price map: `model.fitOutPricing.basic`, `.moderate`, `.complex` (numbers, ex GST).
  - Replaces the v1.11 motor-HP heuristic for fit-up tier selection on models where the operator has set explicit values.
  - Admin UI: new fields on HighfieldModelEditor + BoatsTable expanded-row panel.
  - Resolver hook: `resolveFitOutPrice(model, tier)` returns explicit value if set, falls back to the v1.15 classification rules, falls back to the v1.11 HP heuristic.

- **2.3.1 Quote Variations (post-contract)**
  - After a quote is locked + sent, a "Create variation" action opens a variation editor.
  - Variation is a separate doc at `users/{uid}/quotes/{qid}/variations/{vid}` with delta lines (added options, removed options, price adjustments) + a status (draft / sent / accepted / rejected).
  - Variation PDF renders only the delta + the new total (not a full re-quote).
  - Send-variation pipeline mirrors v1.13 send-service-quote and v1.8 send-quote: render → upload → mail/{id} → audit → auto-lock.
  - Out of scope for variations: contract re-signing flow (lands with 2.6.3 in same cycle if there's time, otherwise v1.20).

### Phase B — Variation acceptance (1 story)

- **2.6.3 Customer Agreement on Variation**
  - Public accept-variation page: customer clicks a link from the variation email, sees the delta, accepts via signature pad + IP/UA timestamp.
  - Acceptance writes to `variations/{vid}.acceptedAt` + `.acceptedByName` + `.acceptedSignatureDataUrl`.
  - Salesperson dashboard surfaces a "Pending customer agreement" pill for any sent variation not yet accepted.
  - Out of scope: full contract re-signing (still v1.20 / Epic 2.4.4).

## Risk / unknowns

- **2.2.1 GM override UX scope creep**: easy to slip into "approval workflow" with multi-step routing. Discipline: GM is just any user with the `can_override_margin` permission flag; override is a single action with a required reason field. No queue, no email-out, no multi-stage approval. Reporting on overridden quotes lands in v1.20.
- **2.1.2 fallback chain confusion**: explicit per-model values, then classification rules, then HP heuristic — three layers is one too many for clarity. Document the priority once in code comments and once in the user guide so operators don't have to guess.
- **2.3.1 variation PDF rendering**: the delta-only format is new. Risk = first PDF looks wrong because the layout was designed for full quotes. Mitigation: render a sample CL380 + accessory-add variation PDF early, send to operator, iterate before locking the format.
- **2.6.3 public-accept page security**: the accept link must be unguessable (random token in URL) and one-time-use. Pattern: store a `variations/{vid}.publicAcceptToken` UUID, validate on the public route, mark consumed on first accept. No login required on the customer side.
