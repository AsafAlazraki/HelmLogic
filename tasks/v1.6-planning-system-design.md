## 2. Data model

### New collection: `epics/{epicId}`

```
title:        string                        (e.g. "Guided Configuration & Quote Creation")
shortLabel:   string                        (≤ 24 chars; rendered as the swim-lane label)
description:  string                        (markdown allowed)
color:        'blue' | 'amber' | 'violet' | 'emerald' | 'rose' | 'slate' | 'indigo'
order:        number                        (fractional index, like features — drag to reorder swim lanes)
status:       'planning' | 'active' | 'done'
createdAt:    Timestamp (serverTimestamp)
updatedAt:    Timestamp (serverTimestamp)
```

Notes:
- No `featureCount` / `totalPoints` denormalization — derive from `features` query at render time. Cheap and never drifts.
- `color` is a palette key, not a hex, so theme tweaks land everywhere at once.
- `status` is informational; the source of truth is the underlying features. UI shows a badge.

### New fields on `features/{featureId}`

```
epicId:     string | null   (FK to epics/{id}; null = unfiled)
points:     number | null   (1 | 2 | 3 | 5 | 8 — Fibonacci; null = unestimated)
deletedAt:  Timestamp | null (set when soft-deleted)
deletedBy:  string | null   (uid of deleter)
```

All four are optional. Existing features without these values render fine (treated as no epic, no points, not deleted).

### Firestore rules update

```
match /epics/{epicId} {
  allow read, write: if isSignedIn() && !isSubDealer();
}

match /features/{featureId} {
  allow read, write: if isSignedIn() && !isSubDealer();
  match /comments/{commentId} {
    allow read, write: if isSignedIn() && !isSubDealer();
  }
}
```

`isSubDealer()` helper checks `users/{uid}.parentOrganisationId != null` (sub-dealers belong to a parent org).

## 3. Sub-dealer gating

**Three layers** so a sub-dealer can't reach the surface even via direct URL:

1. **Sidebar entry** in `nav-links.ts` — hide the Feature Tracking item if the current user is a sub-dealer.
2. **Page-level gate** in `src/app/(app)/feature-tracking/page.tsx` (Server Component) — read user profile, if sub-dealer return `notFound()`.
3. **Firestore rules** — `isSubDealer()` on every read/write to `features` + `epics` (defense in depth).

Sub-dealer detection: `user.parentOrganisationId != null` OR `user.organisationId` belongs to an org that has `parentOrganisationId != null`. Same logic already used elsewhere for sub-dealer pricing.

## 4. UI changes

### 4.1 Tab strip (no shape change, one new tab)

Current: **Board | Release Notes**
New:     **Board | Roadmap | Release Notes**

### 4.2 New: Roadmap view (`src/components/roadmap-view.tsx`)

**Layout** — full-height grid:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  ROADMAP HEADER                                                              │
│  ┌────────┬────────┬────────┬────────┬────────┬────────┬────────────┐      │
│  │ v1.6   │ v1.7   │ v1.8   │ v1.9   │ v2.0   │ Unsch. │            │      │
│  │ 12 pts │ 23 pts │ 18 pts │ 15 pts │ 27 pts │ 8 pts  │            │      │
│  │ Today  │        │        │        │ SCIBS  │        │            │      │
│  └────────┴────────┴────────┴────────┴────────┴────────┴────────────┘      │
├─────────────────────────────────────────────────────────────────────────────┤
│  EPIC 1 — Guided Config       (blue band)                                   │
│  ┌────────┬────────┬────────┬────────┬────────┬────────┐                   │
│  │ ▪▪▪    │ ▪      │        │        │        │        │                   │
│  │ ▪      │        │        │        │        │        │                   │
│  └────────┴────────┴────────┴────────┴────────┴────────┘                   │
│                                                                              │
│  EPIC 2 — Pricing Accuracy    (amber band)                                  │
│  ...                                                                         │
└─────────────────────────────────────────────────────────────────────────────┘
```

Where each `▪` is a small feature card chip (just the title + points badge, click to open the existing detail sheet).

**Header column widths**: equal flex, scrollable horizontally on narrow screens.

**Header per-release content**:
- Release label (`v1.6`)
- Sum of `points` of features in that release (`12 pts`)
- Today pill if `RELEASE_WINDOWS[release]` contains today's date
- SCIBS pill on the release flagged `isMVP: true` (v2.0)
- Background tint: amber if sum > 25, red if sum > 40

**Drag and drop**: cards can be dragged between cells (changes `targetRelease` and/or `epicId`). If dropped into an amber/red release, show a brief warning toast — but allow it. Reuses the same `@dnd-kit` infrastructure as the Board.

**Empty cell**: subtle "—" placeholder.

**Filter bar (top)**:
- Filter by epic (multi-select)
- Filter by status (Submitted / Under Review / Planned / In Progress / Shipped)
- Toggle: "Show unestimated" (cards without `points`) — ON by default

**Release windows** (const map, lives in `src/lib/release-schedule.ts`):

```ts
export const RELEASE_WINDOWS: Record<string, { start: string; end: string; isMVP?: boolean }> = {
    'v1.6': { start: '2026-04-27', end: '2026-04-30' },
    'v1.7': { start: '2026-05-01', end: '2026-05-06' },
    'v1.8': { start: '2026-05-07', end: '2026-05-11' },
    'v1.9': { start: '2026-05-12', end: '2026-05-15' },
    'v2.0': { start: '2026-05-16', end: '2026-05-19', isMVP: true },
};
```

Trivial to update when the plan shifts. SCIBS marker is implicit from `isMVP`.

### 4.3 Board view changes

- **Grouping toggle in banner**: `Group by: Status (default) | Epic`. When grouped by Epic, columns become Epic 1 / Epic 2 / .../ Unfiled instead of Submitted / Under Review / etc.
- **Epic chip on cards**: small color-banded chip under the title showing the parent epic. Click → opens an "Epic detail" sheet (next).
- **Points badge on cards**: e.g. `5 pts` next to the priority badge.

### 4.4 Create dialog + Detail sheet additions

Two new fields:
- **Epic** — Select with all epics (or "No epic"). Color-coded options.
- **Story points** — Select with `Unestimated / 1 / 2 / 3 / 5 / 8`.

Detail sheet auto-saves on change (same pattern as priority/release).

### 4.5 Soft delete + Archive

- **Confirm dialog** on Delete (already there as `confirm()` — keep).
- On delete, set `deletedAt` + `deletedBy` instead of `deleteDoc`.
- Board / Roadmap queries add `where('deletedAt', '==', null)` filter (use `firestore.where` or filter client-side; client-side is simpler given small data size).
- New **Archive view** under the existing tab strip (or as a sub-toggle in the banner): shows soft-deleted features with a Restore button + permanent-delete button (admin only).
- 30-day cleanup is a manual operation for v1.6 — write a small script in `scripts/purge-archived-features.ts`. Auto-cleanup via Cloud Function is deferred (would need scheduled function infra).

### 4.6 Epic management UI

Small admin surface — `/feature-tracking?view=epics` (or a "Manage epics" button on the Roadmap):
- Lists all 5 epics
- Inline edit title / shortLabel / color / order
- Drag to reorder
- Add / archive epic

For v1.6 this can be a bare-bones list — we don't need pretty.
