## Decisions Locked In (Don't Re-Litigate)

From the design doc review with the user:

1. **One module, many brands (Option A)** — not one module per brand
2. **New vendor type `Trailer Brand`** — alongside Boat Brand / Motor Brand / Internal
3. **Full price levels** — hull_cash, hull_trade, hull_subdealer, hull_subdealer_excl, hull_aus_sailing (same as motors)
4. **NO Promotions tab** — trailers don't get promotions (unlike Yamaha)
5. **Per-boat-model trailer assignments** — each boat model has its own `trailerAssignments[]` with pre-configured dealer fit (mirrors Motor Options pattern)
6. **Quote Step 4 reads assignments, not single trailerConfig** — default pre-selected, user can switch
7. **Dealer fit on Trailers module** — `moduleDealerFitCategories` on the Trailers module itself (not per boat module); boat module's existing `trailerDealerFitCategories` becomes fallback
8. **Excel import per brand** — same as MPF. Each brand has its own upload.
9. **One trailer per quote** — multiple trailers per quote is out of scope for v1.4

## When The Excel File Arrives

Order of operations:

1. Read the file structure (sheets, columns, sample rows)
2. Identify the brands present (Mackay? Dunbier? Easytow? Jurgens? Others?)
3. Map columns to the design's expected schema (Model, Length, Weight, Capacity, Cost, price levels, specs)
4. Note any columns that don't fit — ask user rather than guess
5. Write a parse strategy doc (`tasks/v1.4-excel-parse-strategy.md`)
6. Begin Phase 1 (enum additions)

The expected columns per the design doc (§4):
- **Required**: Model, Length, Weight (Tare), Capacity (ATM)
- **Pricing**: Cost, NSM Retail / Cash Price, Trade Price, Sub-Dealer Price, Sub-Dealer Excl Price, AUS Sailing Price
- **Specs**: Axles, Suspension, Brakes, Tyres, Drawbar, Hub Type, Lights
- **Optional**: Image URL, Notes, Compliance details

Real file will likely be "annoyingly laid out" (user's words). Be flexible — write `getTrailerField(row, field)` helper that tries multiple casings, like `getMotorName()` does for Yamaha.

## Known Gotchas (Apply These From Day 1)

Pulled from `CLAUDE.md` — worth restating in the trailer context:

- **`priceLevels` object on every trailer row** — don't rely on `sellPriceExclGst` alone
- **`getPriceForLevel()` is the ONLY correct way to display price** — never hardcode `sellPriceExclGst` on cards, heroes, or grids. Regression that hit motors in v1.2.1 will hit trailers if we're not careful.
- **Inc GST `Math.ceil()` to whole dollars** per item row
- **Firestore `in` query capped at 30** — slice `trailerBrandVendorIds` if it ever exceeds 30 (unlikely but cheap insurance)
- **Loading overlay for TrailersWorkspace MUST be scoped to the active tab** — not a page-root overlay. v1.3.1's lesson applies.
- **URL-sync state** — `?trailerBrand=`, `?trailerTab=` etc. should sync to URL. Apply the same partial-param inference pattern as modules/[id]/page.tsx.
- **useMemoFirebase, not useMemo** — for any Firestore ref
- **`<img>` not `<Image>`** for external trailer CDN URLs
- **`optional().nullable().default()` + `.passthrough()`** on the Zod schema for trailer rows — legacy data will have missing/weird fields

## Testing Strategy (from design doc §12)

Manual test cases go into `testing/v1.4/test-cases.md` (create when the release folder is made). Key flows:

1. Create new Trailers module (admin)
2. Add brand vendors, import Excel per brand
3. Edit a brand's pricing, confirm flow to quote
4. Assign trailers to a Highfield CL340 model via new Trailer Options tab
5. Build CL340 quote → Step 4 shows only assigned trailers, default pre-selected, pre-configured DF auto-ticks
6. Switch trailer → DF re-evaluates
7. Sub-dealer view → trailer shows Trade price
8. Finalize → payload snapshots brand + assignmentId

Playwright: new `tests/trailers-module.spec.ts` with ≥5 tests covering workspace load, brand filter, detail sheet, pricing tab, quote Step 4 assignment flow.
