## Story slate (6 shippable + 3 NSM-Hub conditional + 1 spike)

### Phase A — Catalog polish (5 stories)

- **3.10.4 Saved filter views per user**
  - Saved filters live as an array field on the user profile doc (`users/{uid}.savedCatalogFilters: { id, name, query, createdAt }[]`). No new Firestore collection so no rules deploy needed.
  - Chip row above the Catalog Manager cross-tab search input. Click a chip, search applies. X removes the filter.
  - "Save current" button visible when there's an active search term. Opens a name-it dialog.
  - Per-user, not per-org, so an admin and a salesperson can each have their own pinned views.

- **2.1.1 Structured Price Sources**
  - Today every read site re-derives the priceLevels object on the fly. This story formalises the canonical shape into `derive-pricing.ts` (extends the v1.17/3.2.1 layer) and adds `resolvePriceLevel(priceLevels, level, fallbackOrder)` so the lookup logic lives in one place.
  - Migrate motor cards + hero card + finalize payload to the new resolver. Boat hull pricing slips to v1.19 (more invasive).

- **Edit Stock Item**
  - One-row inline editor on the module dashboard's Stock Management section. Click a stock row, edit quantity / location / status, save.
  - Foundation for v1.21 Pending Units (you can't track pending units without a stock-row editor).

- **Export Data — brand → range → model**
  - Per-tab CSV from v1.14 is one flat list per vendor. Operators want the full hierarchy in one CSV for accounting + import-back. New "Export hierarchy" button on Catalog Manager → one combined CSV with brand / range / model columns + every spec + pricing.

- **Receipt PDF branding**
  - Deposit receipts (v1.20) need to inherit the same branding tokens (logo, font, colour) as the quote PDF. This story sets up the shared `pdfBranding.ts` resolver so the receipt-PDF (v1.20) just consumes it.

### Phase B — First customer-facing surface (1 story)

- **1.4.2 Send Quote Action (boat side)**
  - Mirrors the v1.13/11.2.4 service-quote send pipeline. Send button on the proposal view → render PDF → upload to `users/{uid}/quotes/{qid}/sent/{sendId}.pdf` → write `mail/{id}` for the Trigger Email extension → write `sentEmails/{sendId}` audit → bump `sentCount` + `lastSentAt` → auto-lock on first send.
  - Gated on `NEXT_PUBLIC_EMAIL_SEND_ENABLED` (already in place from v1.8).
  - Same toast + tooltip pattern as the service-quote version so the muscle memory carries.

### Phase C — Shopify spike (no shippable deliverable, time-boxed half-day)

- Goal: understand Shopify Admin API in the HelmLogic context. NOT shipping anything to users.
- Read-only spike script in `/tmp/shopify-spike/`:
  - Auth: private-app token vs OAuth Admin API, pick the path that makes sense for a per-dealer install.
  - Pull product list + variants + inventory levels, dump to JSON.
  - Map: what would HelmLogic push to Shopify (boat catalog → Shopify products?). What would HL pull (Shopify orders → HL Pending Units?). What's bidirectional (stock visibility)?
- Output: `tasks/shopify-exploration-notes.md` with findings, recommended integration shape, and a v1.21+ story slate proposal for when it formally lands.
- Zero production paths touched. The spike script stays in `/tmp` or in a private `tasks/shopify-spike/` folder ignored by git.
