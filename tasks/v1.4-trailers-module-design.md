# v1.4 Trailers Module — Design (Revised)

> Status: Design locked after xlsx analysis (see `FINDINGS.md`).
> Branch: `Dev` (all trailer work lands here).
> Source data: `tasks/v1.4-trailers-source/Trailer Module.xlsx` (LFS, 6.58 MB, ~455 trailers).

## 1. Summary of decisions

| # | Topic | Decision |
| --- | --- | --- |
| 1 | Hierarchy | `data-warehouse/{brandVendorId}/series/{seriesId}/trailers/{trailerId}` (mirrors Highfield `ranges/models`) |
| 2 | Pricing | **Ingest the full waterfall** — top-level essentials for sales, `pricingDetail` for dealer audit |
| 3 | Rego | **New Rego module**, shared with boats (replaces ad-hoc `registration` on Highfield quotes) |
| 4 | Dealer Fit | **Module-level** on `modules/{trailerModuleId}.trailerDealerFitCategories[]`, plugged into the existing 3-source merge |
| 5 | Factory Options | Per-trailer `optionalFeatures[]` — same shape as Highfield `model.optionalFeatures` |
| 6 | Rego/compliance form fields (cols KE→NU) | Skipped for v1.4 — revisit in a future Registration module |
| 7 | Obsolete + "Trailer Not Required" rows | Preserved with `isActive: false` |
| 8 | Importer | One xlsx → many vendor docs; `scripts/seed-trailers.ts` mirroring `seed-master-price-file.ts` |

## 2. Vendors

One vendor per trailer brand in `data-warehouse/{trailerVendorId}`:

```
data-warehouse/{trailerVendorId}:
  name: 'REDCO Trailers' | 'TINKA Trailers' | 'STACER Trailers' | ...
  vendorType: 'Trailer Brand'       ← NEW vendor type
  logoUrl: '...'
  currency: 'AUD'
  shortCode: 'REDCO' | 'TINKA' | ...
```

Brands identified from `Dropdowns!R1`:
- REDCO, TINKA (one combined brand per the client's grouping)
- STACER
- DUNBIER
- MACKAY
- GFAB
- NSM CUSTOM

(DUNBIER / HAINES BMT rows import under DUNBIER with a `packageOnly: true` flag.)

## 3. Module document

```
modules/{trailerModuleId}:
  moduleType: 'trailers'
  name: 'Trailers'
  mainVendorId: null                         ← no single main vendor
  trailerBrandVendorIds: string[]            ← all trailer brand vendor IDs in this module
  trailerDealerFitCategories: string[]       ← module-level dealer fit names
  associatedVendorIds: string[]              ← MPF / parts vendors used by dealer fit
  brandCaptainUserId, moduleManagerUserId
  coverImageUrl: string
```

`trailerDealerFitCategories` plugs into the existing 3-source merge in `dealer-fit-options.tsx` — now four sources: global + boat module + motor vendor + trailer module.

## 5. Trailer document

```
data-warehouse/{trailerVendorId}/series/{seriesId}/trailers/{trailerId}:

  // Identity
  code: 'RE1213'                     ← col E (unique within brand, used as doc ID when safe)
  name: 'REDCO Sportsman - RE1213'   ← col C
  longDescription: string            ← col F
  imageUrl: string                   ← col G
  isActive: true

  // Specs (col H–O)
  specifications:
    boatSizeMtr: number
    wheelSize: string
    tareKg: number
    atmKg: number
    winch: string
    betweenGuardsMm: number
    lengthMtr: number
    plug: string

  // Free-text features (cols R–AL concatenated, drop blanks)
  features: string[]

  // Primary pricing — used by the quote flow
  cost: number                       ← col BS Total Nett CTD
  sellPriceExclGst: number           ← col BW Sell
  landedCost: number                 ← col AS

  // Full waterfall — for dealer audit / Pricing Manager
  pricingDetail:
    dealer: number                   ← AN
    discount: number | null          ← AO
    settlement: number | null        ← AP
    nettPrice: number                ← AQ
    freight: number                  ← AR
    landed: number                   ← AS
    pdOperation: string              ← BB
    pdHours: number                  ← BC
    pdDollars: number                ← BD
    pdParts: Array<{ name, cost }>   ← BE/BF/BG/BH/BI/BJ/BK/BL/BM/BN pairs
    sundry: number                   ← BO
    detailing: number                ← BP
    totalPdCharges: number           ← BQ
    totalNettCtd: number             ← BS
    markupPercent: number            ← BT
    grossProfit: number              ← BU
    rrp: number                      ← BV
    sell: number                     ← BW

  // Factory options (cols CD–FX, 20 slots × 4 fields)
  optionalFeatures: Array<{
    id: string
    name: string                     ← e.g. 'EX050ADDG'
    description: string
    cost: number
    sellExclGst: number
  }>

  // Lead times (cols AU–AZ)
  leadTimes:
    factoryLeadDays: number
    lockoutDate: Timestamp | null
    factoryBuildDate: Timestamp | null
    factoryCompletionDate: Timestamp | null
    factoryShippingDate: Timestamp | null
    estimatedLeadDays: number

  // Supplier metadata
  supplier: string                   ← col D

  // Source tracking
  importedAt: Timestamp
  importedFromFile: 'Trailer Module.xlsx'
  sourceRow: number
```

All prices stored `sellPriceExclGst`; GST applied at finalize via `Math.ceil(x * 1.1)` per existing CLAUDE.md rule.

## 6. Rego module (new)

Replaces the ad-hoc `registration: { boatRego, sticker, tenderTo, trailerRego }` on Highfield quotes. Applies to **both boats and trailers**.

### Module document
```
modules/{regoModuleId}:
  moduleType: 'rego'
  name: 'Registration Types'
  mainVendorId: null
  regoVendorIds: string[]
```

### Rego vendor
```
data-warehouse/{regoVendorId}:
  name: 'Queensland Registration' | 'NSW Registration' | ...
  vendorType: 'Rego Authority'
  currency: 'AUD'
  state: 'QLD' | 'NSW' | 'VIC' | ...
```

### Rego type doc
```
data-warehouse/{regoVendorId}/regoTypes/{regoTypeId}:
  name: 'Small Trailers - Up to 1.02t'
  sellExclGst: 151
  appliesTo: 'trailer' | 'boat' | 'both'
  description: string
  isActive: true
```

### Quote flow integration
- Rego picker becomes a dropdown of `regoTypes` filtered by `appliesTo` and the user's state.
- Selected rego type is snapshotted into the quote like motor prices (`resolvePrice()` pattern): `quote.trailer.rego = { id, name, sellExclGst, snapshotAt }`.
- Boat rego picker in `highfield-quote-flow.tsx` migrates to the same dropdown. Old free-text amounts stay readable for historical quotes.

## 8. Importer

`scripts/seed-trailers.ts` — mirrors `scripts/seed-master-price-file.ts`.

### Flow
1. Parse `Trailer Module.xlsx` with `xlsx` / `exceljs`.
2. Read `Dropdowns!R1` for the canonical brand list.
3. Walk the `Trailer Module` sheet, detecting:
   - **Brand header rows** (text in col C matches `Dropdowns!R1`, no `Code`)
   - **Series header rows** (text in col C, no `Code`, under a known brand)
   - **Trailer rows** (any row with a `Code`)
4. For each trailer:
   - Resolve/create the brand vendor (`data-warehouse/{brandVendorId}`).
   - Resolve/create the series doc (`…/series/{slugified-name}`).
   - Upsert the trailer doc (keyed by `code`).
5. Mark `Obsolete Trailers` and `Trailer Not Required` sections with `isActive: false`.
6. Pre-import dry-run writes a JSON plan to `/tmp/trailer-import-plan.json` for review.
7. Import triggered by a server-side admin action (`/data-warehouse/trailers/import`).

### Dry-run output shape
```json
{
  "brands": [
    { "vendorId": "redco", "name": "REDCO Trailers", "seriesCount": 11, "trailerCount": 125 },
    ...
  ],
  "totals": { "series": 53, "trailers": 455, "skipped": 0 },
  "warnings": ["Row 4 had a code but no series — assigned to 'Unsorted'", ...]
}
```

## 9. Workspace UI

`src/components/trailers-workspace.tsx` — modelled on `YamahaMotorWorkspace` but without Promotions.

### Tabs
- **Catalog** (grouped by brand when "All Brands" selected; flat when filtered)
- **Pricing Manager** (shows `pricingDetail` waterfall per trailer, editable per org override)
- **Settings** (Import Excel, Dealer Fit Categories, Brand Management)

### Catalog card
- Image (fallback: Truck icon)
- Brand badge (brand-coloured)
- Name + code
- Length + ATM badges
- Price chip (`Sell inc GST` — rounded up per CLAUDE.md rule)

### Pricing Manager
- Read-only view of `pricingDetail` from the source import.
- Editable `sellPriceExclGst` override per org (writes to `organisations/{orgId}/trailerOverrides/{trailerId}` — new, mirroring `modelOverrides`).
- Waterfall rendered as a vertical breakdown so the dealer can audit each step.

## 10. Out of scope for v1.4

- Registration/compliance data capture (cols KE–NU).
- Per-trailer promotions (no Promotions tab).
- Trailer colour/material variants (the data has none).
- Migration of historical Highfield quotes onto the new Rego module — new quotes only; old quotes keep their `registration` object.
